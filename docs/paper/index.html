01 问题02 方法03 结果04 负结果05 限制06 复现

01 / PROBLEM

长期智能体评测很容易把脚本成功误写成能力。

当任务规则变化、工具失败、记忆过期或目标漂移时，一个得分无法说明系统究竟在适应、记忆、重试还是碰巧成功。LongRun-AGI 先构造可控制的对照，再冻结任务和失败，最后把每项输出封装为带来源与哈希的工件。

02 / METHOD

八个工作包，一条证据链。

P1—P8 覆盖验证器缺口、故障恢复、可溯源记忆、世界模型、证据门、目标漂移、CLEAR 基准和算力控制。CLEAR-300-v1 冻结 300 个任务并划分为 180/60/60；模型协议目前只在 240 个 train/dev fixture 上完成干运行，60 个测试任务保持封存。

每次运行保留原始 JSON、命令、环境、来源哈希和明确边界。组合审计只检查这些记录是否一致，不把完整性升级为科学发现。

03 / RESULTS

我们能够支持的结果。

P2 / 恢复

在五类临时文件系统和子进程故障中，重规划为 5/5，纯重试为 0/5。

P3 / 记忆

SQLite 存储经重启后检索正确率 1.0，毒化/过期选择率 0.0，批回滚保持原子性。

P5 / 声明

严格 schema 将构造集中的假发现从 60 降至 0，但有效发现率降至 0.5。

P7 / 协议

脚本化当前规则策略成功率 1.0，粘滞旧规则策略 0.3133；这是 harness 对照，不是模型行为。

04 / NEGATIVE RESULTS

失败不是附录。

P4 / 世界模型

OOD 错误 AUROC 为 0.5，不确定性惩罚规划没有超过 argmax。

P6 / 目标漂移

虽然留出 AUROC 为 0.8295，但提前预警率为 0，干预未提高最终正确率。

P8 / 自适应控制

成功率 0.4833，记忆写入为 0；尚未接入真实工具、检索器或 token 成本。

05 / LIMITS

这份证据没有跨过的边界。

  • 没有下载、加载或评测语言模型。
  • 没有外部 benchmark 或 leaderboard 结果。
  • 本地 mocks 与临时进程不等于真实浏览器、游戏或生产环境。
  • 没有完成新颖性评估、论文审稿或外部独立复现。
  • 不能从这些探针推断 AGI 进展。

规范边界见 PORTFOLIO-STATUS.md 与 MODEL-GATE.md。
